# Mac MPS 首轮实验记录 · 2026-09-06

## 本轮完成了什么

新版连续动作 LocalGP–MAPPO 已在本机 Apple Silicon 的 MPS 上实际训练。三个训练种子为 7、17、27，各运行 16,384 个环境步，总计 **49,152 步**。另完成了 32 步冒烟训练。每个完整训练种子按日志累计约 118 秒；这一口径不含依赖安装、进程启动和最后一次更新之后的尾部评估及保存。

最终回归测试 **64 项全部通过**，包含真实 MPS 前向、反向、PPO 更新与检查点恢复，没有跳过 MPS 测试。CPU 同环境下，中断恢复后的下一批数据以及下一次更新的 Actor/Critic 参数与连续训练逐位一致。最后保留的弃用警告来自旧版 `forth/` 的 SciPy 距离接口。

## 预先固定的实验条件

- 3 架 AeBS、50 个用户、100×100 米区域、24×24 信念图，最大速度 2 m/s，航程预算 100 米，最小机间距离 2 米。
- 每回合最多 64 秒，用户移动、测量噪声、信道参数、GP 参数及奖励权重均保存于配置和 manifest。
- 默认 `balanced` 感知代理奖励；两个独立网络分别承担 Actor 和集中式 Critic。
- 验证场景种子：100000–100003。按验证回合内平均吞吐量选检查点，选取规则在测试前确定。
- 独立测试场景种子：200000–200007。所有策略使用同一组场景；三个训练种子下的随机、感知贪心、固定向右、静止基线结果完全一致，已核验。
- 种子 7 在 4096 步后从检查点续训至 16384 步；其余两个种子从头训练。续训最佳产物继承修复不改变训练计算。

为了公平比较提前耗尽航程的策略，最终报告补充了**统一 64 秒窗口**的覆盖率、吞吐量和累计传输量。任务提前结束后的时间不再计入服务。这是本实验的记账规则，不是对真实设备停止移动后通信能力的断言。检查点没有根据这一补充指标或测试表现重新选择；补充前后检查点哈希相同，原有指标也已核对一致。

## 测试结果

以下数值先在每个训练种子的八个测试场景上取平均，再在三个训练种子间取平均。所有吞吐量和覆盖率均为统一时间窗口口径。

- **训练策略：平均覆盖率 49.79%，吞吐量 6.729 Mbps，累计传输量 430.63 Mbit。**
- **固定向右半速（不用 GP）：平均覆盖率 62.02%，吞吐量 8.689 Mbps，拒绝移动事件为 0。**
- **感知贪心：平均覆盖率 54.91%，吞吐量 4.817 Mbps。**
- **随机策略：平均覆盖率 20.48%，吞吐量 3.368 Mbps。**
- **原地不动：平均覆盖率约 20.46%，吞吐量 3.240 Mbps。**

三个训练种子的个体结果：

- **种子 7：** 选中 8192 步检查点。覆盖率 30.08%，吞吐量 4.637 Mbps；平均每回合 22.63 次拒绝移动事件。[逐帧报告](../../output/study-seed7/report.html)。
- **种子 17：** 选中 16384 步检查点。覆盖率 58.81%，吞吐量 8.162 Mbps；平均每回合 46.25 次拒绝移动事件。[逐帧报告](../../output/study-seed17/report.html)。
- **种子 27：** 选中 16384 步检查点。覆盖率 60.48%，吞吐量 7.388 Mbps；这八个测试回合的拒绝移动事件为 0。[逐帧报告](../../output/study-seed27/report.html)。

这里的“拒绝移动事件”包含边界和机间距离约束拦截，不是已经发生的物理碰撞。贪心基线的平均拒绝事件为 42.13 次。报告中的硬约束拦截不能代替对真实平台安全性的验证。

三个训练种子的平均覆盖率的样本标准差为 **17.09 个百分点**，吞吐量均值的样本标准差为 **1.853 Mbps**，说明训练初始化仍有明显影响。这些统计量描述的是在同一组八个场景上、三个训练种子之间的变化，没有将 24 个结果错误地当作 24 个独立训练。

## 几何基线诊断

初次评估后发现，所有无人机固定从区域西侧出发，而用户初始簇中心落在区域中部。这可能让向右飞行本身就获得很大收益。因此补充固定向东、最大速度一半的基线，到东侧边界后停止；它只使用当前位置与区域尺寸，不使用 GP、测量或真实用户状态。该诊断是在查看首轮结果之后加入的，没有重新训练、调参或重新选择检查点。

这个简单基线在相同八个测试场景上的平均覆盖率和吞吐量，均超过三个训练种子各自的场景均值。这不足以推断所有分布下的优劣，但明确表明：目前不能把相对随机策略的提升归因于 GP 感知或学习决策。

## 可以得出的结论

1. MPS 训练、正确的逐智能体 GAE、检查点恢复和可追溯评估已经形成可运行的闭环。
2. 在这组初步实验中，训练策略的平均吞吐量超过了随机和固定感知贪心基线，三个训练种子的平均覆盖率均超过随机基线。
3. 覆盖率与吞吐量存在权衡：训练策略的跨种子平均覆盖率仍低于贪心，且种子 7 明显弱于另外两个种子。
4. 固定向右半速基线更强，暴露出初始布局先验与代理奖励的局限；GP 的额外贡献尚未证明。当前结果不足以宣称算法优势、统计显著、真实部署有效或完成论文复现。

下一轮首先随机化机群出发方向与位置，对场景做旋转对照，检查固定方向策略是否仍占优势；随后在相同预算下比较完整 GP、移除 GP 图层和固定几何路线，隔离感知贡献。同时对齐代理奖励与累计通信服务目标，处理跨种子稳定性和无效移动。使用新的留出测试种子，增加独立训练种子、用户分布和信道扰动，随后再讨论模型规模或训练时长。任何下一轮调整都使用新的实验标识，保留本轮原始结论。

## 如何核验与复现

[机器可读记录](mps-2026-09-06.json)已进入 Git，包含全部训练种子和测试种子、完整环境配置、每场景结果、基线、检查点 SHA-256、评估文件 SHA-256、训练源提交和源文件哈希。

训练产物和报告位于本地 `output/`，不把检查点与大量逐帧数组加入源码历史。原始训练日志分别在 `output/mps-seed7/`、`output/mps-seed7-16k/`、`output/mps-seed17-16k/`、`output/mps-seed27-16k/`；最终报告在 `output/study-seed*/`。

执行示例，输出目录需尚不存在：

```sh
python -m localgp.train --config configs/mac.json --seed 17 --steps 16384 \
  --output output/reproduce-seed17
python -m localgp.evaluate output/reproduce-seed17/best.pt --device mps \
  --episodes 8 --seed 200000 --output output/reproduce-evaluation17
python tools/build_training_report.py output/reproduce-evaluation17
```

环境版本见 `requirements-training-verified.txt`。原实验在 PyTorch 2.14.0、Python 3.12.14 上运行。跨设备、系统或库版本不承诺逐位一致。
